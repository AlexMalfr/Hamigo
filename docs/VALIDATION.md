# Validation de Hamigo

Vérification du 4 octobre 2026.

- Banque Exam1 : 2 961 identifiants uniques, textes/réponses comparés à la source, 2 961 PNG valides, aucune image manquante. 11 exclusions documentées ; 2 950 questions dans le jeu courant.
- Parcours : 21 chapitres, 94 leçons, 826 exercices rédigés ; **18 catégories de ressources et 390 flashcards**. Une exécution isolée du générateur, avec écritures interceptées, correspond octet pour octet aux deux JSON actuels : les reformulations Morse sont conservées. Le catalogue procédural contient 5 188 variantes.
- **41 tests JVM réussis** : 16 règles d'apprentissage, quatre du générateur étendu, six outils mathématiques, deux séances aléatoires, trois messages de rappel, cinq contrôles de calculatrice et cinq de segmentation/normalisation Morse.
- **63 tests instrumentés hors réseau GitHub validés**, sur Pixel 9a Android API 36 : état Compose, parcours utilisateur, relecture et finalisation d'examen sans doublon, transparence/recadrage sans modifier l'image originale, drag & drop, associations depuis les deux côtés, calculatrice avec insertion, conservation du scroll Mémo, retour prédictif annulé/terminé, progression et plateforme. Les dix tests de transport/OAuth utilisent un serveur HTTP local, dont interruptions avant/après les en-têtes, reprise, PATCH et refus des redirections.
- **Deux tests GitHub réels supplémentaires réussis** depuis Android : le Device Flow intégré renvoie `authorization_pending` ; deux Gists fictifs non répertoriés sont créés, lus, fusionnés, mis à jour par PATCH, relus puis supprimés avec vérification 404. Jeton issu de la connexion CLI existante transféré par stdin vers un fichier privé Android, effacé après l'audit ; préférences et clé Keystore de test isolées. Aucune progression personnelle ni Gist préexistant n'est utilisé. Absence du fichier de credential et de l'inventaire de récupération vérifiée.
- **152 captures Android revues** : cinq onglets, réglages, cours, questions/corrections, introductions d'épreuves, original et zoom, récapitulatif, 18 ressources et outils, recherche/en-tête fixe, invitations, quatre types de posters, rappels et les 48 poses/expressions de Pico. Preuves finales dans `output/visual-audit-delivery/`, après rétablissement du fond bleu-vert des outils. La passe complète est conservée dans `output/android-tests-0.6-final.txt` (63 tests exécutés, deux tests réseau réel ignorés sans leur option explicite) ; réseau réel dans `output/github-live-tests-fixes.txt`. Les échecs initiaux de sélecteurs, l'écart d'un canal au décodage PNG et l'ANR de System UI sur l'émulateur restent dans les rapports historiques ; les cas corrigés ont ensuite été validés avec l'interface système rétablie.
- Assemblage debug et APK de tests réussis. Lint debug : aucune erreur, **55 avertissements et une indication**, principalement des API Android/Compose anciennes et des suggestions KTX.
- Application OAuth GitHub commune Hamigo réellement enregistrée avec Device Flow activé ; identifiant public intégré dans l'APK. L'endpoint de demande de code accepte cet identifiant. Aucun secret OAuth n'a été créé pour l'app Android.
- Page HTTPS d'invitation et fichier Android Asset Links publiés et accessibles en HTTP 200. Le certificat annoncé correspond à la signature de release locale, exclue de Git.
- Dépôt GitHub AlexMalfr/Hamigo vérifié privé. La version Android utilise le nombre de commits et la révision Git. La livraison construit l'APK signé depuis un commit propre, vérifie sa signature, met à jour le Samsung SM-S938B avec `adb install -r`, puis contrôle la version et la vérification des App Links sur ce téléphone. Les preuves de livraison sont conservées dans `output/`.

La cause précise de l'incident OAuth initial n'a pas été reproduite. Le transport et les opérations Gist sont vérifiés réellement, mais le consentement personnel complet dans la WebView, la réception du jeton OAuth Hamigo et la première restauration depuis le téléphone ne sont pas revendiqués comme testés : ils nécessitent une connexion volontaire depuis l'app. Les rappels sont contrôlés pour leur contenu, illustration, programmation, annulation et heure locale ; Android décide de leur présentation extérieure et peut retarder la livraison sous Doze.

La revue de banque contrôle complétude, intégrité et notes d'obsolescence. Elle ne remplace pas une relecture pédagogique des 2 961 réponses communautaires et de tous les nouveaux cours par un opérateur formateur.

Les correctifs et leurs limites sont détaillés dans [FIXES-2026-10.md](FIXES-2026-10.md). L'audit F6KGL est ciblé sur les lacunes et les ressources figées : il ne certifie pas une couverture exhaustive du programme.
